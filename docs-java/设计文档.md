### 1.2 技术栈对比（Python → Java）

| 层级 | Python版 | Java版 | 优化说明 |
|-----|---------|--------|---------|
| Web框架 | FastAPI | Spring Boot 3.2 | 更成熟的生态和企业级支持 |
| 异步 | asyncio | WebFlux / CompletableFuture | 更灵活的异步模型 |
| ORM | SQLAlchemy | MyBatis-Plus | 代码生成+逻辑删除+分页 |
| 安全 | 手写JWT | Spring Security + OAuth2 | 标准化安全框架 |
| 配置 | Pydantic Settings | Nacos + @RefreshScope | 动态配置热更新 |
| 消息队列 | BackgroundTasks | RabbitMQ | 跨进程、可扩展、持久化 |
| 缓存 | 无 | Spring Cache + Redis | 热点数据缓存，降低DB压力 |
| 监控 | prometheus_client | Micrometer | Spring 生态原生支持 |
| 链路追踪 | 无 | SkyWalking | 分布式全链路追踪 |
| API文档 | FastAPI Swagger | SpringDoc OpenAPI 3.0 | 更规范的接口描述 |
| 事务 | 手动 | @Transactional 声明式 | 编程模型简化 |

```
│                                                              │
│  输入输出:                                                    │
│  输入: 歌词文本 + 旋律(MIDI/参考音频/自动生成)               │

│  输出: WAV/MP3 歌唱音频                                      │
│                                                              │

│  public interface SingingEngine {                             │
│      boolean isAvailable();                                   │
│      SingingResult synthesize(SingingRequest request);        │

│  }                                                           │
│                                                              │
│  SingingRequest:                                             │
│  - lyrics: String          歌词                              │
│  - melodySource: Enum      旋律来源(MIDI/REFERENCE/AUTO)     │
│  - melodyData: byte[]      MIDI文件或参考音频                │
│  - voiceModelId: String    声音模型ID(复用VoiceModel)        │
│  - style: String           演唱风格(pop/opera/rap/...)       │
│  - tempo: float            速度(BPM)                        │
│  - key: int                音调偏移(半音)                    │
│  - format: String          输出格式(mp3/wav/flac)            │
└──────────────────────────────────────────────────────────────┘
```

**技术方案**：

| 方案 | 引擎 | 说明 | GPU需求 |
|------|------|------|---------|
| RVC (推荐) | RvcSingingEngine | Retrieval-based Voice Conversion，零样本声音转换，输入原唱+目标声音模型 | 需要 |
| DiffSinger | DiffSingerEngine | 歌谱驱动合成，输入MIDI+歌词，生成对应旋律的歌声 | 需要 |
| So-VITS-SVC | SvcSingingEngine | 需要训练声音模型，质量最高但周期长 | 需要 |
| Edge-TTS降级 | EdgeTtsSingingEngine | 无GPU时降级，使用Edge-TTS朗读歌词（非真唱） | 不需要 |

**核心流程**：
```
用户输入歌词 + 选择旋律 → 确定声音模型 → 选择引擎 → 生成旋律 → 声音转换 → 后处理(混响/均衡) → 输出音频
```

**优化**：
- 声音模型复用 `VoiceModel`（与声音克隆共享）
- 训练任务复用 RabbitMQ Worker
- GPU 推理通过 Python 子进程调用（与声音克隆一致的 ProcessBuilder 模式）
- 后处理（混响、均衡、降噪）使用 Java TarsosDSP 库

| 方案 | 引擎 | 说明 | 生成时间 | GPU需求 |
|------|------|------|---------|---------|
| CogVideo (推荐) | CogVideoEngine | 智谱开源文生视频，中文理解好 | 2-5min/10s | A100推荐 |
| Stable Video Diffusion | SvdEngine | Stability AI 开源，图片驱动 | 1-3min/4s | 需GPU |
| Sora API | SoraApiEngine | OpenAI Sora 商业API，质量最高 | 30s-2min | 无(云端) |
| Wanx API | WanxApiEngine | 阿里通义万相API，国内访问快 | 1-3min | 无(云端) |
| Mock降级 | MockVideoEngine | 开发测试用，生成静态图片序列 | 1s | 无 |

**核心流程**：
```
用户输入描述/图片 → 选择生成模式 → 选择引擎 → 推理生成 → 后处理(编码/水印) → 存储MinIO → 通知用户
```

**关键设计**：
- 视频生成是重GPU任务，必须异步（RabbitMQ + 专用GPU Worker）
- 任务状态机：pending → queued → generating → processing → completed / failed
- 支持 WebSocket 推送进度（比轮询更实时）
- 视频文件存储到 MinIO，前端通过签名URL访问
- 生成完成后自动添加水印（版权保护）
- 支持批量生成（同描述多seed对比选优）

## 6. 关键设计决策

### 6.1 异步任务：RabbitMQ 替代 BackgroundTasks

| 对比项 | Python BackgroundTasks | Java RabbitMQ |
|--------|----------------------|---------------|
| 执行位置 | 进程内 | 独立Worker进程 |
| 持久化 | 无（重启丢失） | 消息持久化 |
| 扩展性 | 单进程 | 水平扩展Worker |
| 监控 | 无 | RabbitMQ Management |
| 重试 | 手写 | 死信队列自动重试 |

**消息流程**：
```
生产者 → Exchange → Queue → Worker → ACK/NACK → 死信队列
```

### 6.2 缓存策略：Spring Cache + Redis

| 缓存场景 | Key格式 | TTL | 说明 |
|---------|---------|-----|------|
| 用户信息 | user:{id} | 30min | 读多写少 |
| 会话列表 | convs:{userId} | 5min | 频繁更新 |
| 语音列表 | tts:voices | 1h | 很少变化 |
| 模型配置 | llm:models | 10min | 偶尔变化 |
| 知识库状态 | kb:{id}:status | 1min | 处理中频繁查询 |

### 6.3 流式响应：SseEmitter

```java
@GetMapping(value = "/chat/stream", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
public SseEmitter chatStream(@RequestBody ChatRequest request) {
    SseEmitter emitter = new SseEmitter(300_000L); // 5分钟超时
    
    chatService.chatStream(request, new StreamCallback() {
        @Override
        public void onToken(String token) {
            emitter.send(SseEmitter.event().data(Map.of("type", "token", "content", token)));
        }
        @Override
        public void onDone(ChatResponse response) {
            emitter.send(SseEmitter.event().data(Map.of("type", "done", "usage", response.getUsage())));
            emitter.complete();
        }
        @Override
        public void onError(Exception e) {
            emitter.send(SseEmitter.event().data(Map.of("type", "error", "message", e.getMessage())));
            emitter.complete();
        }
    });
    
    return emitter;
}
```

### 6.5 GPU 推理任务队列

AI唱歌、视频生成、人物替换均为 GPU 密集型任务，采用专用 GPU Worker 模式：

```
┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│  Java Service │────▶│  RabbitMQ    │────▶│  GPU Worker  │
│  (生产者)    │     │  GPU Queue   │     │  (Python)    │
│              │     │              │     │              │
│ - singing    │     │ - singing_q  │     │ - RVC推理    │
│ - video      │     │ - video_q    │     │ - CogVideo   │
│ - deepfake   │     │ - deepfake_q │     │ - FaceFusion │
└──────────────┘     └──────────────┘     └──────┬───────┘
       ▲                                         │
       │           ┌──────────────┐              │
       └───────────│  结果回调    │◀─────────────┘
                   │  (MQ/WebSocket)│
                   └──────────────┘
```

**设计要点**：
- GPU Worker 独立部署为 Python 容器（复用现有推理生态）
- 通过 RabbitMQ 双向通信：Java发任务 → Worker消费 → Worker发结果 → Java更新状态
- 支持 GPU Worker 水平扩展（多卡场景）
- 任务状态机：pending → queued → processing → completed/failed
- WebSocket 推送进度（替代轮询）
- 无 GPU 时自动降级（Mock引擎/云API）
